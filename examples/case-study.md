# 实测案例：给工业编程 Agent 做配方（2026-10）

> 这是专业软件案例的早期数据（v0.1，单路线配方）。多路线迭代的例子见 `tia-portal/modify_block_routes.md`；通用任务上的完整结果见 [`../RESULTS.md`](../RESULTS.md)。

## 环境
- Agent：一个基于 LangGraph 的工程助手（DeepSeek v4 flash），通过 MCP 驱动 Siemens TIA Portal（开源的 TIA Portal Openness MCP）。
- 真实软件、真实工程副本；每次运行都是全新 Agent 进程、全新数据目录、全新 MCP 服务器进程、全新工程副本，单轮任务。
- A = 用户原话；B = 原话 + 配方 v1；C = 原话 + 配方 v2（修正 v1 的错误）。配方附在用户消息后（流程指导型）。

## 结论
1. **配得准的流程指导型配方确实有用**：调用降 30–65%，费用降 17–40%，失败归零，质量不降。读取类任务收益最大。
2. **写错的配方比没有更糟**：漏一个必填参数 → 每次多失败一次；塞了用户没问的步骤 → 调用翻倍、还漏答。所以上线前必须过「静态体检 + A/B 对比」。
3. **配方只覆盖用户问到的范围**。
4. **写类任务的收益更多来自服务器自带的写法指南**：无配方时也全部一次编译通过，配方只省掉「读指南、看示例」那几次调用。
5. **组合执行型（服务器侧一次拿全的工具）先起作用**：同一个大工程总览，一个月前没有「一次拿全统计」的工具时第一轮要 50 次调用，有了之后无配方也只要 18 次。配方在此基础上再降到 13 次。

## 外部试用：拿到本包的另一个 Agent 能不能做对
给一个对本次实验毫不知情的较小模型（Claude Haiku）只提供本包，让它按 SKILL.md 第 3–4 步给新任务（「列出每台 PLC 的变量表及标签数」）写配方并自查。结果：第一次体检即合格（8 处工具调用、326 个工具的清单里全部对得上），并主动列出 3 处没实测确认的返回字段假设。据此在 SKILL.md 补了「待验证」标记和「连接/接管类前提由人确认」两条。

## 本地工作流（给 Claude Code 用）的两个组合执行型实例
- **真机验证固定入口**：用例脚本只写「调什么、期望什么」，复制工程、判失败、必错哨兵、收尾统一处理。同一组 14 项真机验证从 104 行减到 78 行，3 份只差路径的复制版合并成 1 份，结果与手写版一致。
- **一条命令发版**：13 个本地步骤（改版本号 → 编译 → 生成清单 → 测试 → 泄露扫描 → 提交 → 重编 → 部署 → 打包 → 与上一版对比 …）一口气跑完，在推送前停下；推送另起一条命令，需要人批准。每一步报「完成 / 失败 / 未执行」，失败可从断点续跑。演练中故意写入的客户名被泄露扫描拦下；一次真实的脚本缺陷（漏传环境变量）也按契约报出「停在第 11 步、前 10 步已完成、后 2 步没做」，修复后续跑完成。
