# 配方：日志里找某时间段出错最多的接口和原因

**适用**：「某时段哪个接口报错最多」「统计 5xx / ERROR 并找原因」这类按时间窗聚合日志的请求
**不适用**：要实时盯日志、要改服务配置的
**前提**：日志是按行的文本（可能有轮转压缩的 .gz）

## 选路
| 条件 | 走 |
|---|---|
| `command -v zcat grep awk` 都有 | 路线 A |
| 没有这些命令（如 Windows cmd） | 路线 B |

## 路线 A：一条管道统计（默认）
1. `ls -la <日志目录>` —— 看文件名里的时间和大小；**带 .gz 的是轮转压缩的，同样要算**
2. 看格式：`zcat -f <任一文件> | head -n 3`，确认时间戳、状态码、错误原因各在哪
3. 只读时间窗覆盖的文件（按文件名挑），**用一条管道过滤 + 计数**，不要把整份日志读进来：
   `zcat -f <文件...> | grep '<时间前缀>' | grep -E '<错误标记>' | <取出接口和原因> | sort | uniq -c | sort -rn | head`
4. 交叉核对：换一种口径数一次同一接口的次数（例如访问行里的状态码 vs 错误行），两者一致才写结论；不一致先查原因
5. 按要求格式写结果文件；数字直接用命令输出，不估算

**成功判据**：第 4 步两种口径的次数一致
**失败时**：命令不存在 → 转路线 B；其它失败 → 停下报告停在哪一步

## 路线 B：写一个流式解析脚本（备用）
1. 同路线 A 第 1、2 步（没有 head 就用读文件工具读前几行）
2. 写一个 Python 脚本：逐行读（`.gz` 用 `gzip.open(..., "rt")`），正则取时间/接口/状态/原因，`Counter` 计数，打印前几名
3. 同路线 A 第 4、5 步

**成功判据**：同路线 A
**失败时**：停下报告

## 不要做
- 不要用读文件工具或 `cat` 把整份日志读进对话（几十万行会撑爆上下文、浪费 token）
- 不要只看未压缩的文件
- 不要统计时间窗以外的行
